# Suggested Features

## Context

An earlier version of this file (generated by an external AI code review) proposed a large 
research-grade roadmap: multi-season walk-forward backtesting, uncertainty/probability 
modeling, projection ensembles, correlation/stacking analysis, playoff-window dynamic 
weighting, and more. That analysis was analytically well-reasoned but scoped for a 
completely different kind of project — a research platform with multiple seasons of 
historical data, not a personal decision-support tool for one user's one team in one 
league, currently in its first season of use.

Building that roadmap would take more effort than playing the season it's meant to help 
with, and much of it depends on data (historical ADP, consensus rankings across seasons, a 
completed backtest holdout season) this project doesn't have and doesn't need. It's also 
worth flagging that several of that document's cited sources had unusual, unverified URLs — 
treat any external research citations in this project's history with skepticism unless 
independently checked.

This replacement file keeps only the two ideas from that review that are genuinely useful 
at this project's actual scale, with no new infrastructure required.

## 1. "No meaningful edge" threshold for lineup swaps

The project already has per-position VOR thresholds for streaming adds (low bar for 
QB/TE/K/DEF, high bar for RB/WR). Extend the same thinking to the intra-roster bench-vs-
starter comparison notes: if a bench player only narrowly out-projects a starter (a small, 
noisy margin), don't present it with the same confidence as a clear, decisive edge. This 
avoids the tool implicitly encouraging weekly lineup churn over projection noise.

- Add a configurable margin (e.g. `lineup_swap_margin: 1.0` in config.yaml) — a bench 
  player must beat a starter's projection by at least this much for the comparison note 
  to read as "starts over" rather than a softer "close, no clear edge" framing.
- This is a small tweak to existing comparison-note logic, not new infrastructure.

## 2. Lightweight personal results tracking

Each week's report is already saved to `reports/`. Add a simple, optional way to compare 
what was recommended against what actually happened, once real scores are in — not a 
statistical backtest, just a personal record for the season.

- A small script (e.g. `track_results.py`) that takes a past week's saved report plus that 
  week's actual final scores (entered manually or pulled from ffbot if available after the 
  week completes), and produces a short summary: which recommended moves paid off, which 
  didn't, and whether the position-comparison notes were right about who should have 
  started.
- No modeling, no calibration, no walk-forward evaluation — just an honest record to look 
  back on periodically, for personal interest.

## Explicitly not pursuing

Uncertainty/probability modeling, projection ensembles, joint MILP lineup optimization 
beyond what `ffbot` already provides, correlation/stacking analysis, playoff-window dynamic 
weighting, multi-season backtesting, and a full decision ledger are all out of scope for 
this project. If the project's scope ever genuinely changes (e.g., managing many leagues 
across many seasons), these ideas could be revisited — but not before then.
